# 变声器功能 · 开源方案调研

> 调研日期：2026-09-30。星数 / 许可证 / 最近提交均通过 GitHub API 实时核对。

## 一、结论

「录/传一段音频 → 换成指定音色」在技术上分两条完全不同的路线，别混为一谈：

| 路线 | 做法 | 是否保留原声语气 | 新增依赖 | 落地成本 |
|------|------|------------------|----------|----------|
| **A. ASR → TTS 重合成** | Whisper 转文字 → 用现有克隆音色重新念一遍 | ❌ 丢情感/停顿/语速 | 0（宝螺已有 whisper + Genie-TTS + ffmpeg） | 1～2 天 |
| **B. 真·语音转换 SVC** | 音频 → 模型直接换音色，内容和语气都保留 | ✅ | 一个新 python 环境 + 每个音色一份模型 | 1～2 周 |
| **C. 零样本 VC** | 给 10～30 秒参考音频即可换音色，不用训练 | ✅ | 一个新 python 环境（推理重） | 3～5 天（效果待实测） |

**建议：先上 A 做功能闭环（复用已有克隆音色体系，纯 CPU、零新依赖），再按用户反馈决定是否补 B。**
如果用户真正的诉求是「把自己有权处理的素材换个音色继续用」，A 就够；如果是「保留原口播的抑扬顿挫」，只能走 B。

## 三、和宝螺现有代码怎么对接

路线 A 几乎是「拼装已有零件」：

1. **音频输入**：上传走 `dialog.showOpenDialog`（参考 `src/main/ipc.ts` 现有用法）；录音在渲染层用 `MediaRecorder` 采 webm，再走 ffmpeg 转 16kHz 单声道 wav（`src/main/dialogue/ffmpeg.ts` 已有封装）。
2. **转写**：直接调 `src/main/transcribe.ts` 的 `transcribeVideo()`，它已经做了 mp4→wav→whisper-cli 的全流程。
3. **重合成**：用 `src/main/dialogue/genie-manager.ts` 启动本地服务，`GenieTtsEngine.synthesize()` 按用户选的克隆音色逐句合成（`src/main/dialogue/compose.ts` 里已有逐句合成 + 拼接的实现，可直接参考）。
4. **成片**：ffmpeg 把音频并回原视频（贴到原视频上做「变声版」）或直接输出 wav/mp3（`voice:saveMp3` 已有）。
5. **界面**：新建 `src/renderer/views/VoiceConvertView.tsx`，音色选择复用 `src/shared/voices.ts` + `CloneVoice` 列表。

路线 B 需要新增的东西：一个独立的 python 环境（RVC/DDSP-SVC，含 torch，体积远大于现在的 Genie），每个目标音色一份训练产物（约 50～150MB），以及一次离线训练流程。**别打进安装包**，按需下载。

## 四、许可证与合规（重要）

宝螺本身以 MIT 开源发布，但**AGPL / GPL 项目不能直接链接进安装包**（会把派生作品也拖进强 copyleft）：

- 可放心用（MIT / Apache）：RVC、Applio、DDSP-SVC、OpenVoice、Genie-TTS、GPT-SoVITS、MeanVC、Amphion、GPA。
- 需规避或仅作思路参考：so-vits-svc（AGPL）、so-vits-svc-fork（未声明，上游 AGPL）、Seed-VC（GPL-3）、voice-pro（GPL-3）。
- 另需留意：音色克隆用于仿冒他人声音在国内已有判例风险，产品文案上建议明确「需获得音色本人授权」。

## 五、建议的落地顺序

1. **P0（1～2 天）**：路线 A 闭环 —— 上传/录音 → 转写 → 选已有克隆音色 → 重新合成 → 试听/下载。纯 CPU、零新依赖，先让功能可用。
2. **P1（视反馈）**：接入 RVC（MIT）做真·变声，先用官方预训练音色验证效果与 CPU 实时率，再决定是否做训练入口。
3. **P2**：如果用户要「麦克风实时变声」，去看 w-okada/voice-changer 的客户端架构（注意许可证）。

**最大风险**：CPU 推理慢。Genie 在纯 CPU 上约 0.2～0.5 倍实时率，1 分钟音频要等 2～5 分钟；RVC 纯 CPU 推理比训练轻，但同样吃 CPU。界面必须给进度和「预计耗时」，否则用户会以为卡死。

## 六、路线 B 对电脑配置的要求

要拆成两件事看，**它们对配置的要求差一个数量级**：

| 环节 | 谁来做 | 需要什么 | 多久一次 |
|------|--------|----------|----------|
| **训练**（把音色素材变成模型） | 可以是你，在开发机上做 | NVIDIA 显卡 4GB+ 显存（官方 FAQ：4GB 以下直接放弃） | 每个音色一次 |
| **推理**（用户上传音频→输出变声） | 用户电脑，必须能跑 | 纯 CPU 即可，有显卡更快 | 每次使用 |

**训练侧（我们自己的事，不占用用户配置）**

- 数据量：10 分钟低底噪干声（RVC 官方推荐下限）。
- 显卡：RVC 官方 FAQ 原文——「4G 以下显存（例如 1060 3G 和各种 2G 显卡）可以直接放弃，4G 显存显卡还有救」，缩到 batch_size=1 仍 OOM 就只能换卡。**6～8GB 显存舒适**。
- 时长：10 分钟数据在 3060 级别显卡上大约 0.5～2 小时。
- 没有 NVIDIA 卡：AMD / Intel 走 DirectML，Linux 走 CPU，慢一个档次；CLI 理论支持 `--device cpu` 训练，实际慢到不可用。
- DDSP-SVC 的官方定位就是「能在个人电脑上普及的免费 AI 变声软件」，硬件要求比 so-vits-svc 低一个数量级，训练速度接近 RVC，实时变声资源消耗略高于 RVC——**如果训练机配置一般，优先选它而不是 RVC**。

**推理侧（用户电脑的真正门槛）**

- RVC 官方 CLI 支持 `--device cpu`，纯 CPU 能跑通，所以**离线变声不强制要求显卡**。
- 有 NVIDIA 显卡会明显更快（显存 4GB+ 即够，推理比训练省得多）；无显卡时预计慢于实时，**具体实时率必须在目标机型上实测**，别拍脑袋承诺。
- 内存：推理 8GB 起够；训练建议 16GB（RVC FAQ 里有「提取特征时内存炸掉」的条目）。
- 磁盘：音色模型约 50～150MB/个。
- **最大的体积坑**：官方 RVC / DDSP-SVC 都依赖 PyTorch，环境约 1.5～3GB，是现在 Genie 便携 Python 的好几倍。而宝螺现有的便携 Python 里已经有 `onnxruntime 1.22.1`，如果将来找到成熟的 ONNX 版推理，可以复用现有环境、完全免 torch——目前社区 ONNX 方案还不成熟，别把产品押在上面。
