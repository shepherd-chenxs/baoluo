# 变声器（方案 A）· 产品设计与实现说明

> 方案选型见同目录《变声器功能-开源方案调研.md》。本文只写 A 方案（识别 → 换音色重念）的落地细节。

## 一、功能定位

**一句话**：上传一段音频或视频，把里面的人声换成你指定的音色重新念一遍。

**和 B 方案（RVC 等真·语音转换）的取舍**：A 方案不保留原声的语气、停顿、语速，
换来的是零新增依赖、纯 CPU 可用、直接复用已有的克隆音色体系。
适合"用自己拥有权利的素材，统一账号音色"这类场景；要保留原口播抑扬顿挫的需求只能走 B 方案。

## 二、用户流程

1. 侧边栏「变声器」→ 选择音频 / 视频文件（mp4 / mp3 / wav / m4a / flac…）
2. 选目标音色：在线音色（Edge TTS，可调语速/音调/音量）或本地克隆音色（滑杆置灰）
3. 点「开始变声」，界面实时显示四个阶段：
   提取人声 → 识别文案（带滚动实时文本）→ 逐句重新配音（第 n/共 m 句）→ 拼接
4. 试听结果，可「保存为 MP3」（默认，会自动转码）或「打开所在文件夹」

全程有一个跳动的「已用时」，避免用户以为卡死（纯 CPU 逐句合成的确慢）。

### 关键技术点

- **采样率统一**：克隆音色输出 32kHz wav、在线音色输出 24kHz mp3，拼接前统一转成
  32kHz / 单声道 / pcm_s16le，再用 ffmpeg concat demuxer 拼（路径用正斜杠 + 单引号转义）。
- **单句失败不中断**：与「视频生成」同样的策略，某句合成失败就跳过该句继续，
  最后在结果里报「成功 x/共 y 句」；全部失败才报错。
- **中间产物即用即删**：切句音频（seg/）、归一化音频（norm/）、concat 列表跑完就清，
  用户目录里只留一条 `voice.wav`。
- **进度不串台**：变声器走自己的 `voice-convert:progress` 通道，且只发回发起方窗口，
  语音识别页不会被带跑。
- **旧结果清理**：与语音合成一致，只保留最近一次的 `voice-convert-output/vc-*` 目录。
- **错误文案**：克隆音色加载失败会明确提示「先去设置 → 声音克隆启动本地服务」，
  而不是抛 `ECONNREFUSED`。

## 四、已验证（本机实测）

| 场景 | 结果 |
|------|------|
| 在线音色（云健 → 晓晓） | 源 9.38s → 成品 9.00s，3 句，全流程 9.3s |
| 克隆音色（feibi 模型，CPU） | 2 句全部成功，成品 5.04s，全流程 36.2s（含服务启动 6.4s） |
| 类型检查 / 构建 | `tsc`（renderer + main）与 `vite build` 均通过 |
| 既有测试 | `npm test`（解析器 + Genie 安装/后台任务）全部通过 |

## 五、已知边界与后续可做

1. **不支持麦克风录音**：当前只能选本地文件。录音要在渲染层用 `MediaRecorder` 采集
   → IPC 落盘 → ffmpeg 转 wav，属于纯增量小改。
2. **不保留原时间轴**：现在是顺序拼接。若要"替换原视频音轨还能对上口型"，
   需要按识别出的时间戳给每句加静音间隔（PCM 定长写入或 adelay 拼接），
   同时接受"新配音比原句长时会顶掉后面"的现实。
3. **不输出视频**：只给音频，替换音轨让用户自己用剪辑软件做（避免做成音画不同步的半成品）。
4. **长音频很慢**：Genie 在纯 CPU 上约 0.2~0.5 倍实时率，10 分钟口播可能要十几分钟。
   后续可加「只处理选中片段」或接入 B 方案。
