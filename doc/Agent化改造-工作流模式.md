# 工作台 · 工作流模式（讨论稿）

> 问题：「这些跟直接点菜单有什么区别？」——先把区别说准，再说怎么做出「工作流感」。

## 一、现在真正的区别

| | 手点菜单 | 工作台 |
|---|---|---|
| 链条 | 人肉串：A 页的产物复制到 B 页 | 建卡时就把步骤排好（`buildSteps` 一次生成），跑之前看得见全貌 |
| 中间产物 | 各页各存各的草稿 | 每步产物落 `task.workDir`，原片另进素材库，能单独拿走 |
| 返工 | 只能整页重来 | 单步重跑，下游自动打回未开始（`runTask` 的 only 分支） |
| 进度 / 取消 | 每页一套 | 一条时间线，卡在哪一步看得见 |

还有一条容易被忽略的：**「执行」本来就是一路跑到底**——`runTask` 不给 stepId 时，从第一个没做完的步骤一直跑到最后。所以工作台不是"一步一点"，是"点一次，串着跑"。

## 二、现在真的没区别的地方

**1）单步能力建卡 = 换了个入口。** 语音合成、语音识别都只有一步：一张卡、一个「执行」，跟去对应菜单页填个表单没有本质差别。不调模型、不串接、不复用——这类能力单独建卡是负收益。

**2）参数每次从零调。** 音色、画面比例、语言……每张新卡都要重选一遍，不记得上次用了什么。

**3）「该你了」被做成了「出错了」。** 跑到选图那一步，抛的是红字错误 + 任务状态 `failed`。用户读到的信息是"失败了"，而不是"轮到你填了"。

## 三、做成「工作流模式」的五件事（按性价比排）

1. **断点即交互**：需要人拍板的步骤（选图、选音色、选题）不算失败。跑之前标「等你」，跑到了就停在那一步，卡上亮一句「该你了：选两张图」。
2. **参数跟人走**：同一意图的**上次选择**自动带出来（音色 / 比例 / 语言），新卡默认就是上次那套。
3. **单步能力不单独建卡**，改成链条里的环节：「变声」已经是「识别 → 换音色重念」，语音合成 / 识别同理，作为别人的一步更值钱。
4. **配方**：一次调好的卡存成模板，下次一句话复用（「按上次那套再来一条」）。
5. **批量**：一次贴 5 条链接 → 5 张卡排队跑，人只看结果。

第 1 条是"工作流感"的地基：没有它，工作台永远像"点按钮"，不像"跑流程"。

## 四、一句话

工作流的价值不在「能聊天」，在**链条、断点、复用**三件事上。单步能力放进来只会稀释它。
