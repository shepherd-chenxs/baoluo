# 把模型与数据挪出 C 盘 · 方案讨论

> 现状实测（2026-09-30，本机）：`%APPDATA%\Baoluo` 合计 **5.3 GB**

| 目录 | 体积 | 说明 |
|------|------|------|
| `genie` | **4.08 GB** | Genie 角色模型（feibi/mika/thirtyseven）+ GenieData 公共资源 |
| `runtime` | 720 MB | 首次使用声音克隆时下载的便携 Python + 依赖 |
| `Cache` | 268 MB | Electron/Chromium 缓存（可清、可改路径） |
| `models` | 141 MB | whisper 识别模型（ggml-base.bin） |
| `video2c-tmp` | 62 MB | 视频转码临时残留（启动时可清） |
| 其它（输出/克隆参考音频/配置） | < 15 MB | dialogue-output、clone-refs、settings.json 等 |

真正的"大户"只有三样：**Genie 模型 4 GB、便携 Python 720 MB、whisper 模型 141 MB**。

## 三个方案

### 方案 A：数据目录可配置（推荐）

设置里增加「数据目录」，默认仍是 `%APPDATA%\Baoluo`，用户可改到 `D:\宝螺数据` 之类；
改的时候提供「迁移现有数据」（带进度），或「仅切换、模型重新下载」。

- 优点：符合主流做法（VS Code / 剪映 / 微信都是这套）；不动安装包结构；卸载逻辑好处理。
- 缺点：需要一次性迁移 UI + 迁移期间的空间校验（目标盘要能放下 5 GB）。
- 技术要点：
  1. 固定位置的"指针文件"`%APPDATA%\Baoluo\dataRoot.txt` 记录数据目录（必须留在 AppData，否则找不到它）；
  2. `setupUserDataDir()` 读指针 → `app.setPath("userData", 目标)`，保持"ready 之前、任何模块读写之前"的现有约束；
  3. Chromium 缓存单独处理：启动参数 `--disk-cache-dir` 指到数据目录（顺手解决那 268 MB）；
  4. 卸载脚本 `build/installer.nsh` 跟着改：按指针文件删，而不是固定删 `%APPDATA%\Baoluo`。

### 方案 B：数据放安装目录（便携）

数据跟着 exe 走，拷贝整个目录就能换机。

- 优点：真·绿色版体验，一个目录全带走。
- 缺点：安装到 `C:\Program Files` 时**没有写权限**（需要管理员），必须先判断可写、否则回退到 AppData；
  卸载/升级会连带数据；同一台机器多用户会互相覆盖。
- 建议：**另出一个「便携版」安装包**（electron-builder 的 portable/zip target），而不是把正式版改成这样。

### 方案 C：只挪大件

只把 `genie` + `runtime` + `models` 三项做成可配置（约 4.9 GB），配置和缓存留在 AppData。

- 优点：改动最小（只动 genie-manager / transcribe 的路径来源），迁移页面也简单。
- 缺点：仍是两处数据，用户理解成本略高；"到底哪份是干净的"要靠文档说清楚。

## 建议

**先做方案 A，工程量约 1 天**：设置里选数据目录 + 一键迁移 + 卸载脚本适配；
顺手清掉 `video2c-tmp` 残留、把 Chromium 缓存指到数据目录。
如果只求最快见效，就退化成方案 C（半天）。

## 需要你定的两件事

1. 走 A 还是 C？（A 更干净，C 更快）
2. 迁移时默认行为：**复制**（保留原数据，占双份空间）还是**移动**（复制成功后删源，省空间但中途失败要能回滚）？

---

## 已实施：方案 A（2026-09-30）

**用户怎么用**：设置 → 通用设置 → 数据目录 → 「更改…」→ 选一个新盘目录（如 `D:\宝螺数据`）
→ 确认 → 等待复制进度 → 「立即重启生效」。

**实现要点**

| 事项 | 做法 |
|------|------|
| 数据目录来源 | 指针文件 `%APPDATA%\Baoluo\data-root.txt`（必须留在 AppData，否则找不到数据在哪） |
| 启动时生效 | `setupUserDataDir()` 读指针 → `app.setPath("userData", 目标)`，仍满足"ready 之前、任何模块读写之前"的约束 |
| 目录无效时 | 指针里的目录不存在（比如移动盘没插）→ 自动回退默认目录，不让应用起不来 |
| 迁移策略 | **复制→校验成功→写指针→清空旧目录**；中途失败旧数据完整、下次启动仍走旧目录 |
| 空间校验 | 迁移前用 `fs.statfsSync` 比对目标盘可用空间，不够直接拦下 |
| 防呆 | 目标目录不能与当前数据目录互相包含（避免越拷越多的递归） |
| Chromium 缓存 | 启动参数 `--disk-cache-dir <数据目录>/cache`，C 盘的 268 MB 缓存也一并搬走 |
| 卸载适配 | `build/installer.nsh` 先读指针文件，勾选"清除应用数据"时会连自定义目录一起删 |
| 顺手清理 | 启动时删除老版本遗留的 `video2c-tmp` 临时目录（现代码已不引用） |

**测试**：`tmp/datadirtest.cjs`（隔离沙箱，不碰真实数据）13 项全通过——默认目录识别、指针读写、
复制时跳过指针文件、复制后清空旧目录仍保留指针、指针切换生效；NSIS 安装包已重新构建通过。

### 首次实盘迁移踩到的两个坑（已修）

1. **开发模式下点「立即重启」会白屏**：`app.relaunch()` 会把 vite 一起带走，窗口加载不到页面。
   现在主进程判断 `NODE_ENV === "development"` 时不真重启，只提示手动重启；正式版行为不变。
2. **运行中删不掉旧目录**：Genie 服务占着模型文件、Chromium 占着缓存，`clearDataDir` 只能删掉一部分
   （实测 C 盘仍残留 2.71 GB）。现在删失败的目录会记进 `pending-cleanup.txt`，下次启动早期（还没人占用）
   补删一次；本次已手工清干净——C 盘默认目录现在只剩一个指针文件（0 MB），数据全在迁移后的目标目录。
